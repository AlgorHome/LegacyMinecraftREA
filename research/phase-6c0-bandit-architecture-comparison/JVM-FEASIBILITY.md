## Smallest staged independent Java investigation

1. **J0 inventory/load:** choose one reviewed Java21 x64 runtime from its own official distribution, pin every packaged dependency/license/source identity; first package-native control receipt, then one package-relative DLL load/export inventory. No VM or Minecraft. DllMain runs during load, so execution remains separately gated. Imports plus export lookup alone cannot prove Java.
2. **J1 query:** record one invocation-version query per approved profile, numeric result/options digest; no VM. Useful to isolate JNI contract failure but insufficient by itself.
3. **J2 pure Java:** one VM per cold process, minimum reviewed options, interpreter-only first, fixed original class returning a deterministic integer/string checksum. Record JNI_OK, nonnull VM/JNIEnv, observed version/vendor/Java major, fixture hash, exact result, pending exceptions, timing, memory, before/after durable receipts. No filesystem/network/native mod/game/auth fixtures in this case. Success retires a major independent risk even without JIT.
4. **J3 later:** bounded thread attachment/exception/native registration, app-local Java IO/ZIPFS, then JIT witness; each isolated profile. Minecraft/loader experiments only after those prerequisites, under legitimate separate entitlement authorization.

Design a new Java diagnostic identity; never relax the accepted D00 native-only package gate. Do not assume JVM unload/recreate is safe. Preserve native control independently before JVM activity so crash/hang cannot erase prior-stage evidence. Small heap/stack/direct-memory bounds must be set and reviewed before build, not inherited from game options. A watchdog observes, it cannot cancel blocked JNI/driver calls. Current exact runtime/signing/dependency inputs are unselected, so execution readiness is BLOCKED pending review and approval.

Independent implementation should use JNI specification and the selected runtime's own license, not Bandit host/module patches.
