## Seven decision answers

1. **Supported Bandit claims:** official docs describe single-process UWP/JVM, packaged Java families, verified official downloads, native/window/input/loader adapters and legitimate authentication. Pinned source confirms package-relative JVM invocation, loader hooks, WGL current graphics route and the declared manifest. Source presence and README experimental/support labels are not independently verified Xbox gameplay or performance. See UPSTREAM-SOURCE-INVENTORY.md.
2. **What LegacyForge proves:** accepted D00, hardware D3D11, RGBA8 support query, texture creation, SRV creation and backing-resource COM identity, with retained evidence and stated provenance limits. No accepted JVM/JIT/GL/presentation result. The architecture is substantially already present: six sampled production source files byte-match pinned upstream; no new files were imported.
3. **Useful D3D11 work:** native controls, resource/COM ownership and error-isolation/evidence infrastructure remain valuable for any backend and for later native presentation. They do not supply OpenGL/LWJGL compatibility.
4. **Priority:** Path B first; small native part of C next or parallel preparation. A/SRV03 only if owning-device identity resolves a specific dependency. SRV03 is already unsigned-built, not unimplemented or hardware-accepted. No automatic signing/execution.
5. **Next experiment:** first qualify one official Java21 runtime's provenance, licenses and dependency closure read-only; then separately approve J0 load-only. The smallest major functional risk-retiring milestone is J2, one real VM executing an original pure-Java checksum after loader/query prerequisites. Load/export/version-query success alone cannot prove Java. N12 can independently check the D3D12 dependency while Java input review is pending.
6. **Not automatically reusable:** Bandit original host/shim/controller/patches/assets/releases; unspecified Java/Mesa/compiler DLL bundles; generated Minecraft clients and game assets. Independent upstream components may be used only under their actual exact-version licenses/notices/source obligations and applicable permission. Existing overlap does not prove authorship or grants; review before public redistribution.
7. **Next approval:** Phase6C.1 read-only Java21 candidate/license/dependency qualification with no downloads/execution, or explicit original N12 source/unsigned-build approval. With concrete approved runtime inputs, separately approve J0 source/build. Signing, installation-only, one launch, retrieval, acceptance and cleanup each require their own later approval.

## Rationale

Adopting Bandit wholesale would not resolve exact runtime/graphics dependency behavior; the production source already shares those major boundaries. It adds provenance/redistribution questions. Independently designed standards-based probes can retire the open platform risks with original fixtures and no game files, while keeping production auth and installed data unchanged.
