## Evidence model

Every receipt identifies case/subcase, planned uncertainty, package/source/profile/manifest/runtime/native/fixture hashes, OS/build, monotonic elapsed time, numeric errors, measured values and sanitized attachments with SHA256. UTC wall-clock time is additional context, not proof of ordering. A heartbeat/checkpoint before an unsafe stage makes a crash/hang distinguishable from an unstarted case. The owner-reviewed export contains no raw authenticated traffic, personal paths, device identifiers or typed text.

PASS means the declared case oracle was observed. FAILED means the oracle was contradicted. INCONCLUSIVE means execution/evidence was incomplete, including a watchdog deadline. BLOCKED means a prerequisite or approved surface is missing. PLANNED means no execution scheduled. NOT_APPLICABLE cannot satisfy a required gate; NOT_RUN is an unreached-stage marker only. A tested negative request can pass only its negative oracle, never the corresponding positive capability. Actual hardware acceptance is defined separately, not inferred from an all-green schema validator.

Native-control variants D01.native-sentinel, D14.native-storage and D17.native-budget have no VM prerequisite and report only their named native observations. Full S21 D01 still requires the approved runtime/native chain, D14 requires its Java portion and D17 requires post-VM measurements. Receipts bind profile and subcase; the owner may not promote a native-control subcase to the complete S21 case.

For D14, real full-volume/quota preparation belongs to the approved disposable Windows guest, never the console system disk. Xbox negative controls should first use safe app-local cases such as create-new collision in the fixture's own directory. An injected write-error adapter tests only that adapter's handling, not a real OS storage fault. Any unavailable real readonly/quota condition is BLOCKED as its own subcase; do not change console ACLs/capabilities or exhaust storage to force it.
