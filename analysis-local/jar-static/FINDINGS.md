# Focused installed JAR static evidence, 2026-10-17

Scope: installed `legacy/Minecraft/launcher/{launcher,bootstrap}.jar`. Python 3.14.7 `zipfile` and an analyst-written constant-pool/class-structure reader; trusted Ghidra JDK `javap` 21.0.12.1 used only as a static bytecode disassembler with `-p -c -classpath launcher.jar <selected-class>`. No target class initialization, application execution, bundled Java execution, extraction of target bytes, network authentication, or production changes. JSON contains structural metadata and focused method-call/constant observations, not credentials or full bytecode/decompiled listings.

## Identity

**Confirmed:** launcher.jar is 5,496,812 bytes, SHA-256 `364b9add9a3b0e74e553439b3f0e33a573bb5d28667adc028180d509b0459eec`; 1,329 ZIP entries, 1,112 classes. `META-INF/launcher-meta.json` identifies `1.169.4+legacy`, shortBrand `legacy`, brand `Stable`, Java requirement `[11,)`, entry point `net.legacylauncher.LegacyLauncherEntrypoint`, bridged entry `net.legacylauncher.LegacyLauncherBridged`. Launcher manifest has Multi-Release true but no Main-Class. This requirement is for the launcher, not every Minecraft version.

**Confirmed:** bootstrap.jar is 11,026,138 bytes, SHA-256 `09ba7517c8a9b30780ff9a6de230b8905247835ae0da914d66991e2b3b4b6c4e`; 116 outer ZIP entries, 70 outer classes. Manifest Main-Class `org.springframework.boot.loader.JarLauncher`, Start-Class `net.legacylauncher.bootstrap.BootstrapStarter`, Spring-Boot-Version `2.7.18`. `META-INF/bootstrap-meta.json`: `1.40.3+legacy`, Stable. Nested application `BOOT-INF/lib/bootstrap-1.40.3-plain.jar`; common/utils `1.169.3-177-gbe31b827` and bridge JAR also inventoried in memory. Bootstrap application is nested, so the outer class count does not represent the complete application.

**Unknown:** whether these installed files match archive installer contents/acquisition. Do not identify the archive installer by these newer installed metadata values alone. Minecraft selection is a separate setting and is not this launcher version.

## Architecture and desktop assumptions

**Confirmed:** `net.legacylauncher.ui.LegacyLauncherFrame extends javax.swing.JFrame`; packaged FlatLaf 3.4; Java/AWT/Swing desktop UI. `LegacyLauncher` manager accessors identify VersionManager, ProfileManager, JavaManager, LibraryReplaceProcessor, GPUManager, Downloader, MemoryAllocationService. Configuration classes include Configuration/SimpleConfiguration, profile/account state uses Gson.

**Confirmed:** `MinecraftLauncher` defines staged methods `collectInfo`, `downloadResources`, `constructProcess`, `launchMinecraft`, `postLaunch`, `killProcess`, `onJavaProcessEnded`, `onJavaProcessError`. `collectInfo` invokes VersionManager.getVersionSyncInfo -> VersionSyncInfo.resolveCompleteVersion, resolves accounts, chooses JavaManagerConfig, prepares game directories and memory constraints. `launchMinecraft` calls `JavaProcessLauncher.createProcess`, `ProcessBuilder.environment`, `ProcessBuilder.start`, then wraps JavaProcess and attaches logging/hooks. It is an external desktop child JVM model.

**Inferred from class/method inventory and constant-pool references:** bootstrap prepares/downloads launcher dependencies and launches the application via bridge/shared classes or another starter; Bootstrap exposes `downloadLibraries`, `prepareLauncher`, `startLauncher`, self-update and IPC APIs. `SignedStream`, `ChecksumStream`, `Sha256Sign`, `InvalidStreamSignatureException`, and `bootstrap.json.mgz.signed` demonstrate signature/checksum-related implementation surfaces. Full verification policy and all failure paths have not been traced; do not claim every update is cryptographically verified from names alone.

## Installation and launch preparation

**Confirmed:** `OfficialVersionList.getRawList` carries the official manifest URL `https://launchermeta.mojang.com/mc/game/version_manifest.json`, repository selection and response parsing/error paths. `ExtraVersionList.getCompleteVersion` uses `versions/<id>.json`. `CompleteVersion` provides `getRelevantLibraries`, `getClassPath`, `getExtractFiles`, `addArguments`, inheritance/merging methods; Library has rules, OS-native classifier map, extraction rules, download metadata and artifact paths. `Library.appliesToCurrentEnvironment` calls Rule.getAppliedAction. Presence of legacy and modern argument handling is verified in `CompleteVersion.addArguments`.

**Confirmed:** `MinecraftLauncher.downloadResources` selects recommended/current/custom Java configuration, obtains local runtime or remote manifest, tests available space, queues Java installation, VersionManager.downloadVersion and AssetsManager.collectAssets into Downloader, then checks container aborted/error state. Download pipeline is present independently of owning a downloaded full game; installed game inventory must be assessed separately.

**Confirmed:** `AssetsManager` reads local/remote asset indexes, collects missing assets, tests size and optionally hash; hash-aware `checkFile(File,long,String)` invokes `AssetIndex.getHash`. `AssetIndex.getPath` constructs hash-based paths using a substring; resource base `https://resources.download.minecraft.net/` and library base `https://libraries.minecraft.net/` occur in `configuration.Static`. `AssetDownloadable.onComplete` computes SHA digest and rejects hash mismatch. `Sha1Downloadable.onComplete` checks length and SHA-1, throws IOException for mismatches. This is content integrity logic, not publisher authenticity.

**Confirmed:** `unpackNatives` uses ZipFile and Files.newOutputStream/IOUtils.copy into filesystem directories. `constructClassPath` asks CompleteVersion.getClassPath and checks files exist. `CompleteVersion.addArguments` contains `-Djava.library.path=${natives_directory}`, `-cp`, `${classpath}`, launcher brand/version, primary JAR, feature arguments, and platform-specific JVM arguments. `createJvmArgs` adds configured/optimized VM flags, `-Xmx` and `-Dfile.encoding=`. Libraries/natives and working directories remain desktop filesystem assumptions.

**Confirmed:** `JavaRuntimeRemoteListFetcher.doFetch` parses Gson adapters and uses RepositoryProxy.requestMaybeProxy with `https://launchermeta.mojang.com/v1/products/java-runtime/2ec0cc96c44e5a76b9c8b7c39df7210883d12871/all.json`. Runtime selection is keyed by platform and per-version Java component. `JavaRuntimeLocal.getExecutableFile` maps OS/platform to an executable location. `JavaManager.checkIntegrity` obtains manifest integrity entries. LocalDiscoverer, InstallerDirect, InstallerProcess and RuntimeFileDownloadable exist; selected bytecode shows remote acquisition and local installation orchestration, not verified installed JVM operation.

**Unknown:** exact selected game JVM and JNI modules, concrete LWJGL/GLFW/OpenGL/audio dependency versions, loaded native ABI behavior, Forge/Fabric installation semantics and installer execution conditions. These require selected version JSON/native inventory and additional scoped analysis. A class name containing ARM64 fallback is not Xbox compatibility evidence.

## Authentication boundaries

**Confirmed:** `MinecraftOAuthAuthenticate.authenticate` call sequence is Microsoft OAuth authorization-code request -> OAuth token exchange -> XboxLiveAuthenticator.xboxLiveAuthenticate -> XSTSAuthenticator.xstsAuthenticate -> MinecraftServicesAuthenticator.minecraftServicesAuthenticate -> GameOwnershipValidator.checkGameOwnership -> MinecraftProfileRequester.requestProfile (with profile-creation path) -> MinecraftProfileConverter.convertToMinecraftUser.

**Confirmed:** embedded endpoint constants identify `login.live.com/oauth20_authorize.srf`, `login.live.com/oauth20_token.srf`, `user.auth.xboxlive.com/user/authenticate`, `xsts.auth.xboxlive.com/xsts/authorize`, `api.minecraftservices.com/authentication/login_with_xbox`, `api.minecraftservices.com/entitlements/license?requestId=`, and `api.minecraftservices.com/minecraft/profile`. GameOwnershipValidator requests entitlement data with an Authorization Bearer header, rejects empty item lists and requires entries named `product_minecraft` and `game_minecraft`. These describe this installed historical implementation; present-day service contracts require official current verification.

**Confirmed:** PlainUser/PlainAuth and Ely/Mojang/Minecraft account classes coexist. Launcher-local profile selection is not equivalent to Microsoft authentication or Minecraft ownership. Metadata/library/asset fetching is structurally separate from Microsoft account flow; this does not establish rights to play without ownership. Never reproduce third-party account bypass or altered authentication libraries as a legitimate ownership mechanism.

**Confirmed:** `ProfileManager.loadProfiles` and `saveProfiles` use Gson, user/account sets, temporary file output and Files.move; loader includes `launcher_profiles.json` migration. `MinecraftUserJsonizer` serializes a Payload with UUID, name, Minecraft token payload and Microsoft token payload and deserializes them to a MinecraftUser. `LoginCredentials` defines username/session/accessToken/playerName/userType/profileName/properties/uuid; MinecraftLauncher.createArgumentsSubstitutor obtains User.getLoginCredentials().map(). Token values were not inspected. **Unknown:** full storage protection/encryption and redaction policy; do not assert DPAPI or secure vault usage from this evidence.
